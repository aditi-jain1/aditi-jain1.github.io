Project 1: Colorizing the Prokudin-Gorskii Photo Collection

Process Overview

High-level pipeline from BGR plates to aligned RGB output.

Alignment pipeline and design choices

Single-Scale Alignment

Exhaustive search on small windows; aligned directly at a single scale.

For single-scale alignment, I first cropped the images to reduce the influence of noisy borders, which often caused incorrect error or correlation values. I found that I could crop away as much as 30% of the image and still achieve good alignment. I then searched over an offset range of [-15, 15] for both the x and y directions, recording the offset that minimized error (or maximized correlation) between channels. Repeating this process for the red and green channels relative to the blue channel, I then stacked the aligned results to produce the final color image.

cathedral — G Offset: (5, 2) | R Offset: (12, 3)
monastery — G Offset: (-3, 2) | R Offset: (3, 2)

Pyramid (Coarse-to-Fine) Alignment

Multi-scale search to efficiently handle large displacements on high-resolution scans.

However, for larger images this single-scale approach became computationally inefficient, since the true misalignment could span tens or even hundreds of pixels. To address this, I implemented a pyramid alignment strategy. The idea was to first downsample the images and compute the best offset at this coarser scale, where each pixel represented a larger portion of the image. I then used this offset as the center for a smaller search window at the next higher resolution. By iteratively repeating this process through increasingly finer scales, I was able to efficiently “zoom in” on the correct offsets for alignment.

One limitation I encountered was with the Emir image, where I was unable to achieve perfect alignment across all channels. While the blue and green channels aligned well, the red channel consistently lagged behind. The main reason for this is that the red channel has a noticeably different brightness scale compared to the other two channels, making pixel intensity–based comparisons (such as L2 error or cross-correlation) less reliable.

A possible improvement would be to normalize each channel’s intensity values before alignment. For example, rescaling so that the darkest pixel maps to 0 and the brightest pixel maps to 255 (or 1.0 in floating-point representation) would ensure that all channels are compared on the same scale. This normalization step would reduce the impact of brightness differences and make correlation-based alignment more robust.

To further improve both speed and accuracy, I introduced a tiered search window strategy. At lower resolutions (coarser pyramid levels), I used a larger search window since the potential misalignments were bigger. As I moved up to higher-resolution images, I gradually decreased the search window size, which significantly reduced computation time while still refining the alignment.

I also experimented with changing the reference channel. While I primarily aligned the red and green channels to blue, I found that in some cases aligning to the green channel produced better correlation scores and visually improved results. This suggests that the choice of reference channel can matter depending on the image, especially when one channel has brightness or contrast differences (as with the Emir image).

img = cv2.imread('part_1_original.jpg', cv2.IMREAD_GRAYSCALE)
box_filter = np.ones((9, 9)) / 81
dx_filter = np.array([[1, 0, -1]])
dy_filter = dx_filter.T

def conv_4loops(img, kernel):
    padded = np.pad(img, ((kernel.shape[0]//2, kernel.shape[0]//2), (kernel.shape[1]//2, kernel.shape[1]//2)), mode='constant', constant_values=0)
    conv_img = np.zeros_like(img)
    for i in range(img.shape[0]):
        for j in range(img.shape[1]):
            dot_product = 0
            for h in range(kernel.shape[0]):
                for w in range(kernel.shape[1]):
                    dot_product += padded[i+h, j+w] * kernel[h, w]
            conv_img[i, j] = dot_product
    return conv_img

def conv_2loops(img, kernel):
    padded = np.pad(img, ((kernel.shape[0]//2, kernel.shape[0]//2), (kernel.shape[1]//2, kernel.shape[1]//2)), mode='constant', constant_values=0)
    conv_img = np.zeros_like(img)
    for i in range(img.shape[0]):
        for j in range(img.shape[1]):
            conv_img[i, j] = np.sum(padded[i:i+kernel.shape[0], j:j+kernel.shape[1]] * kernel)
    return conv_img

Part A.4: Blend the Images into a Mosaic

I created seamless mosaics using weighted averaging to reduce edge artifacts. The process involves several key steps:

Mosaic Creation Process:

1. Image Warping

Each image is warped into a common coordinate system using the computed homography matrices. This transforms the images so they align properly in the mosaic space.

2. Canvas Sizing

The mosaic canvas is sized to accommodate all warped images, with bounds calculated from the transformed corner points of each image.

3. Distance-Based Alpha Masks

For each image, I create an alpha mask that falls off linearly from the center to the edges. This ensures smooth blending by giving more weight to pixels near the center of each image and less weight to pixels near the edges.

4. Weighted Blending

Images are blended using the formula: final_pixel = Σ(alpha_i × pixel_i) / Σ(alpha_i) where alpha_i is the weight for image i at that pixel location.

5. Seamless Integration

The linear falloff of alpha masks creates smooth transitions between overlapping regions, eliminating harsh seams and creating a natural-looking panorama.

Part 2: Fit a Neural Radiance Field from Multi-view Images

Implementing a complete NeRF pipeline with ray generation, sampling, and volume rendering using the Lego dataset.

Implementation Overview

The NeRF implementation consists of four key components that work together to synthesize novel views from multi-view images. First, I implemented ray generation by transforming pixel coordinates to world-space rays using camera intrinsics and extrinsics, ensuring proper handling of the camera-to-world transformation matrices. The volume sampling component discretizes each ray into sample points with added perturbation during training to prevent overfitting to fixed locations. The network architecture uses a deeper MLP with sinusoidal positional encoding for both 3D coordinates (L=10) and view directions (L=4), with skip connections to preserve input information throughout the network. Finally, volume rendering implements the discrete approximation of the continuous volume rendering equation, computing transmittance and alpha compositing to generate the final pixel colors from the sampled points along each ray.

Can we get rid of the annoying learning rate scheduler? Simplicity is the best. Please try to maintain the same performance after removing the exponential learning rate scheduler. Show your visualization after training without the scheduler and provide a description of what you did to compensate for the loss of the scheduler.

To compensate for removing the exponential learning rate scheduler, I maintained the same initial learning rate (1e-2) throughout training without decay. The training curves show that without the scheduler, the model still achieves similar performance. The loss decreases steadily and the generated samples remain high quality. While the scheduler helps with fine-tuning in later epochs, a constant learning rate works well for this task, especially when training for a fixed number of epochs. The simplicity of a constant learning rate makes the training process more straightforward without significant performance degradation.
